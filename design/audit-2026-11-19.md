# Audit global — Moussaillon 2.5 (19/11/2026)

Audit en lecture seule : **rien n'a encore été corrigé**. Cinq revues parallèles (bugs JS, pédagogie, accessibilité, textes, conformité stores et vie privée) plus une mesure de performances. Les constats critiques et majeurs transverses ont été re-vérifiés dans le code aux lignes citées ; les constats JS critiques et majeurs ont été **reproduits par exécution** (harnais Node dans `tools/audit-harnais/`, non committés : 70 500 questions générées, 2 160 escales simulées, sauvegardes hostiles rejouées).

**Décompte : 5 critiques · 22 majeures · ~62 mineures.** Le socle est très sain : zéro faute d'orthographe dans les milliers de chaînes, zéro exception sur 70 500 questions générées, `check()` juste sur 13 680 réponses testées, aucun appel réseau sortant, contrastes quasi tous AA (calculés), politique de confidentialité fidèle au code point par point.

## CRITIQUES (5)

### C1 · Injection HTML (XSS) persistante via une sauvegarde hostile — JS / sécurité
`src/app.html:1405` (gearOn), vecteurs `:1094` (#import) et `:5986` (« Restaurer depuis un code »), rendus `:1413` et `:5165`.
`gearOn()` renvoie `S.lampOn` / `S.canOn` tels quels dès qu'ils figurent dans `S.gear`, sans vérifier leur appartenance à la liste `GEAR` (contrairement à `gearSel()` pour proue/ancre/chaloupe), et la valeur part sans échappement dans `class="lamp st ${lamps()}"`. **Reproduit** (harness4) : une sauvegarde forgée avec `gear:['"><u id=pwn>…']` injecte du HTML dans la scène de jeu. Portes d'entrée : une URL `…/#import=<base64>` ouverte sur un appareil sans sauvegarde (drive-by premier visiteur), ou un code de sauvegarde collé par un parent.
**Correctif** : dans `gearOn`, n'accepter que les identifiants présents dans `GEAR` (comme `gearSel` le fait via `gearGroup`). Confiance : élevée.

### C2 · Négation enseignée fausse avec le partitif « du » — pédagogie (CE2/CM1/CM2, île conjug)
`src/app.html:3956` (qNeg) et `:4392` (qNeg3). La transformation ne traite que `^(un|une|des)` : avec « manger » (complément « du poisson grillé », `:3850`), la bonne réponse affichée est « Tom n'a pas mangé **du** poisson grillé » au lieu de « pas mangé **de** poisson grillé ». Forme fautive présentée comme correcte. Vérifié dans le code.
**Correctif** : étendre la regex à `du` / `de la` (→ « de » / « d' »), ou exclure les compléments partitifs. Confiance : élevée.

### C3 · « Triangle quelconque » qui peut être rectangle — pédagogie (CE2/CM2, île formes)
`src/app.html:2642` (gFigName, cas 'tri'). 3e sommet `[rnd(18,26)/10, 0]` avec A(0;1,4), B(2,6;1,4) : au tirage 26 (1 chance sur 9), l'angle en B est **exactement droit** (produit scalaire nul, recalculé), mais le jeu réfute « triangle rectangle » par « il n'y en a pas ici ». À 24-25, l'angle paraît droit à l'œil.
**Correctif** : borner x à ≤ 2,2. Confiance : élevée.

### C4 · Questions purement visuelles sans alternative — accessibilité (enfants aveugles/malvoyants)
`src/app.html:1624` (horloge annoncée « Une horloge » sans l'heure), `:5363` (droite graduée sans la position), `:5368` (pizza sans les parts coloriées), `:2560` (figures géométriques au nom générique). Un enfant aveugle ne peut répondre à aucune question des îles Horloge, Jungle, Cuisine, Formes. Comblable au moins pour l'horloge et la droite (aria-label calculé). Confiance : élevée sur le code, moyenne sur le comportement réel de VoiceOver (non testé sur appareil).

### C5 · Écoute anglaise sans option texte — accessibilité (enfants sourds/malentendants)
`src/app.html:5315`, `:5409` (enOK) : le texte anglais ne s'affiche que si l'appareil n'a **aucune** voix anglaise. Un enfant sourd échoue systématiquement les questions « Écoute… » et ne peut pas progresser sur l'Île des Perroquets (4/6 requis). C'est un exercice de compréhension orale, mais un réglage parental « afficher le texte » lèverait le blocage. Confiance : élevée.

## MAJEURES (22)

### Conformité stores (1)
- **M1 · Mode `?admin` atteignable dans l'appli Android (TWA)** — `src/app.html:1100` + `android/…/AndroidManifest.xml:130-140`. La garde n'exclut que Capacitor (iOS). L'appli Android est une TWA du site : un lien `…/?admin` reçu par message ouvre l'appli du Play Store en mode admin (intent-filter autoVerify, pathPrefix="/"). Même risque que le refus Apple 2.2, côté Google (« fonctionnalités cachées », programme Familles). Piste : exclure aussi le display-mode standalone/TWA. Confiance : élevée sur le code, moyenne sur l'appréciation Google.

### Robustesse JS (1)
- **M2 · Sauvegarde importée incomplète → plantage répété** — `src/app.html:1115-1130` (migrate). Une entrée d'île sans `stars/ok/tot/ms` passe la validation puis fait planter l'île (TypeError dans renderIsle `:5207`) et l'escale mélangée (pickQ null dans nextQ `:5286-5307`). **Reproduit** (harness3). Non déclenchable par une sauvegarde produite par l'appli elle-même. Correctif : normaliser chaque île dans `migrate()` à la forme de `IS()` et tolérer `pickQ` null. Couvrirait aussi le « NaN s par réponse » possible avec de très vieilles sauvegardes 1.x (doute non vérifié).

## MINEURES (~62) — par domaine

### Conformité et vie privée (4)
1. Porte parentale : multiplication en lettres lisible par un CM1-CM2 (cœur de cible), réponse gardée côté client (`:5886-5903`) ; format pourtant accepté par Apple (2.5 validée telle quelle).
2. La porte reste ouverte 5 minutes après un passage réussi (`:5888`).
3. `window.__arch` (crochets de test) exposé en production, y compris dans l'appli iOS (`:6403`, copié dans www/). Exploitable seulement via console : risque faible, mais code de test embarqué (règle 2.2).
4. `#import=…` : la sauvegarde transite en clair (base64) dans le fragment d'URL. Jamais envoyée au serveur, nettoyée par replaceState, mais peut rester dans l'historique si le JS ne s'exécute pas. Vigilance, pas une fuite.

### JS (4)
5. `save()` avale en silence un localStorage plein ou bloqué (`:1136`) : progression perdue sans prévenir. Suggestion : toast unique invitant à copier le code de sauvegarde.
6. `__proto__` non filtré dans `JSON.parse` + `Object.assign` (`:1132, :5988`) : pas d'exploitation trouvée, durcissement facile.
7. `pickQ` en fin de banque : jusqu'à 300 générations pour une question, générateurs géométriques coûteux (gPatron) → à-coups possibles sur vieil iPad au rang or (analyse, non mesuré).
8. `escape`/`unescape` dépréciées pour l'UTF-8 (`:1095, :5985`) ; `offerPlacement` crée 15 entrées d'îles dès le premier affichage (gonfle le JSON, sans gravité).

### Pédagogie (37)

### Accessibilité (7)
Contrastes faibles sur éléments secondaires (ratios calculés : « Mers inexplorées » 1,54:1, « ? » mystère 2,81:1, coche ✓ 2,27:1, etc. — tout le reste passe AA) ; jauge juste/faux par couleur seule (daltonisme) ; aria-label qui masquent des infos (rang de l'île, valeur des pièces) ; 3 animations WAAPI hors prefers-reduced-motion (boulet, pluie de doublons, coffre — tout le reste est exemplaire) ; police IM Fell sur des éléments fonctionnels (« Valider », « Feu ! ») ; coffre insensible à la touche Espace ; pas de prefers-contrast/forced-colors.

- **Apple 3.1.1 / Google** : aucun achat ni mention d'achat.
- **Générateurs** : 70 500 questions sans exception ; QCM sans doublon, bonne réponse toujours présente et acceptée, mauvaises refusées (13 680 vérifiées) ; anti-répétition sans boucle infinie ; rangs bronze→argent→or simulés sans anomalie ; progressivité réelle vérifiée générateur par générateur.
